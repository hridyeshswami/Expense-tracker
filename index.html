📐 Entity-Relationship (ER) Schema Model

3rd Normal Form (3NF)

Normalized relational design ensuring referential integrity with cascading updates and zero data redundancy.

👤 users (Parent Entity)
  • 🔑 id (PK, INT)
  • • name (VARCHAR)
  • • email (UNIQUE VARCHAR)
  • • password_hash (VARCHAR)
  • • monthly_income (DECIMAL)
  • • overall_budget (DECIMAL)
🏷️ categories (Lookup Entity)
  • 🔑 id (PK, INT)
  • • name (VARCHAR)
  • • type (ENUM: expense/income)
  • • icon (VARCHAR)
  • • color (VARCHAR)
💳 transactions (Ledger Entity)
  • 🔑 id (PK, INT)
  • 🔗 user_id (FK → users.id)
  • 🔗 category_id (FK → categories.id)
  • • amount (DECIMAL)
  • • is_need (TINYINT: 1=Need, 0=Want)
  • • payment_method (ENUM)
  • • transaction_date (DATE)
🎯 budgets (Allocation Entity)
  • 🔑 id (PK, INT)
  • 🔗 user_id (FK → users.id)
  • 🔗 category_id (FK → categories.id)
  • • month_year (VARCHAR: YYYY-MM)
  • • allocated_amount (DECIMAL)
💰 savings_goals (Entity)
  • 🔑 id (PK, INT)
  • 🔗 user_id (FK → users.id)
  • • title (VARCHAR)
  • • target_amount (DECIMAL)
  • • current_amount (DECIMAL)
  • • target_date (DATE)
🔁 recurring_expenses (Entity)
  • 🔑 id (PK, INT)
  • 🔗 user_id (FK → users.id)
  • 🔗 category_id (FK → categories.id)
  • • amount (DECIMAL)
  • • billing_cycle (ENUM)
  • • next_due_date (DATE)
